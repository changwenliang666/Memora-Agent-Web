## Context

见 `proposal.md` 的动机。当前工作台顶栏右侧是「退出」文字按钮加主题图标；`auth` 会话已含 `account`，但顶栏不展示。登录页独立于 `AppLayout`，手机顶栏与桌面共用 `header-actions`。第一期登录设计明确不做账户下拉，本次补上身份入口。

约束：Vue 3 + Pinia + Element Plus；不新增 UI 库；退出仍走现有 `clearSession` + `/login`。

## Goals / Non-Goals

**Goals:**

- 用一个顶栏控件同时承担身份识别和退出，桌面 / 平板 / 手机共用。
- 头像色与品牌标、侧栏藏青同一谱系，但不做成第二个方形「M」。
- 下拉只放「退出登录」，样式跟表面色、边框、弱化文字走。

**Non-Goals:**

- 不在菜单里展示完整账号、改密或账户中心。
- 不把退出搬进手机抽屉。
- 不新增头像上传或按账号哈希换多种背景色。

## Decisions

### 1. 头像和下拉放在 `AppLayout` 顶栏，抽成 `UserMenu`

在 `src/layouts/UserMenu.vue` 封装头像触发器与下拉，由 `AppLayout` 的 `header-actions` 放在主题按钮左侧。登录页不引用该组件。

备选：逻辑继续堆在 `AppLayout.vue`。否决，下拉挂载到 body 后还要写弹出层样式，壳文件会再膨胀。  
备选：退出放进手机抽屉底部。否决，主题切换已经在顶栏，身份/会话应和它并列；抽屉只负责导航。

### 2. 标识取账号去空白后的后 3 个字符

`label = account.trim().slice(-3)`；空则显示 `···`。JavaScript `slice` 按 UTF-16 码元截取，现有账号是手工输入的拉丁或常见中文，足够用。

备选：显示首字或全部账号。否决，需求明确后 3 位。  
备选：按码点 / 字形簇截取。本阶段账号形态简单，不值得引入分段库。

### 3. 圆形头像 + 靛蓝底 + 白字

新增主题令牌：

- 浅色 `--color-avatar-bg: #1e3a8a`（介于主色 `#1a5cff` 与侧栏 `#0f172a`）
- 深色 `--color-avatar-bg: #3d5bd6`（略深于深色主色，避免和主题图标抢亮度）
- `--color-avatar-text: #ffffff`

尺寸桌面 32px、手机 28px，正圆，字重 600。品牌标保持 8px 圆角方块，头像用圆形以区分「产品」和「用户」。

备选：直接复用 `$color-primary`。否决，顶栏会并排出两个同色色块。  
备选：按账号哈希换色。否决，色板难控，和平台主色容易撞或发脏。

### 4. 使用已有 `el-dropdown`，点击展开，右对齐

`trigger="click"`，`placement="bottom-end"`。菜单目前一项：「退出登录」。弹出层用 `$color-surface`、`$color-border`、`$color-text`，悬停用 `$color-accent-soft`。点菜单外或再点头像关闭，走组件默认行为。

备选：自写绝对定位菜单。否决，手机点按外部关闭和层级要重做。  
备选：`hover` 触发。否决，手机没有悬停。

### 5. 无障碍用完整账号，可见区域仍只显示后 3 位

头像按钮 `aria-label` / `title` 带完整账号（不可展示时用「账户菜单」）。可见文字仍是后 3 位或占位符，避免顶栏被长账号撑开。

## Risks / Trade-offs

- [后 3 位可能撞号] → 本阶段接受；菜单日后可加完整账号行，不改头像规则。
- [下拉挂到 body，scoped 样式打不到] → 用弹出层 class + 非 scoped 或 `:deep` 覆盖，并同时验浅色 / 深色。
- [极短中文或表情截断难看] → 占位与 `slice(-3)` 已覆盖空账号；异常字形保持原样，不额外规范化。
- [手机下拉被刘海或底栏裁切] → `bottom-end` 贴顶栏右侧，菜单向下展开，远离底部安全区。

## Migration Plan

无数据迁移。`memora.auth` 里已有 `account` 的会话直接显示后 3 位；缺账号的旧脏数据走占位符，退出仍可用。回滚即恢复顶栏「退出」文字按钮。
